# Use Markdown Architectural Decision Records (MADR)

## Context and Problem Statement
Technical decisions need to be version-controlled, transparent, and auditable directly within the source repository.

## Considered Options
* Formal Wiki Documentation (Confluence / Notion)
* Markdown Architectural Decision Records (MADR 3.0) in Git
* Pull Request description comments

## Decision Outcome
Chosen option: "Markdown Architectural Decision Records (MADR 3.0) in Git", because it co-locates decisions with source code and integrates directly with Git version control.
